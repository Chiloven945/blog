## 摘要

讓 Java 程式語言持續演進，使初學者無須先理解為大型程式所設計的語言特性，也能寫出他們的第一個程式。初學者不必使用語言的另一種變體；他們可以為單一類別的程式撰寫精簡的宣告，並隨著技能精進，將程式無縫擴充以運用更進階的功能。有經驗的開發者同樣能以簡潔的方式撰寫小型程式，而不必依賴那些面向大規模開發的語言構造。

## 歷史

此功能最初由 [JEP 445](https://openjdk.org/jeps/445)（JDK 21）提出預覽，之後由 [JEP 463](https://openjdk.org/jeps/463)（JDK 22）、[JEP 477](https://openjdk.org/jeps/477)（JDK 23）與 [JEP 495](https://openjdk.org/jeps/495)（JDK 24）持續改進與打磨。我們在此提議於 JDK 25 將此功能定案，並把**簡單**原始檔更名為**精簡**原始檔，同時依據實作經驗與回饋納入若干小幅改進：

- 新的 `IO` 類別（用於基本主控台 I/O）現位於 `java.lang` 套件，而非 `java.io` 套件；因此它會被所有原始檔隱式匯入。  
- `IO` 類別的 `static` 方法不再被隱式匯入至精簡原始檔；因此呼叫這些方法時必須帶上類別名稱，例如 `IO.println("Hello, world!")`，除非明確匯入這些方法。  
- `IO` 類別的實作現在基於 `System.out` 與 `System.in`，而非 `java.io.Console` 類別。

## 目標

- 提供平順的 Java 入門途徑，讓教學者能以循序漸進的方式引介各種概念。  
- 協助學生以精練方式撰寫簡單程式，並能隨著技能提升而優雅地擴充程式碼。  
- 降低撰寫其他類型小型程式（如腳本與命令列工具）時的樣板負擔與繁瑣儀式。  
- 不引入 Java 語言的另一種方言。  
- 不引入獨立的工具鏈；小型 Java 程式應與大型程式使用相同的工具進行編譯與執行。

## 動機

Java 程式語言在由大型團隊於多年期間開發與維護的龐大、複雜應用上表現卓越。它具備資料隱藏、重用、存取控制、命名空間管理與模組化等豐富特性，使元件能在獨立開發與維護的同時，仍可乾淨地組合。藉由這些特性，元件既能為與其他元件的互動揭露定義良好的介面，又能同時隱藏內部實作細節，從而允許各自獨立演進。事實上，物件導向範式的根本，即在於將透過定義良好協定互動的元件拼接起來，同時抽象化實作細節。這種由大型元件組成的方式稱為「大型程式設計」（programming in the large）。

然而，Java 程式語言同時也被設計為適合作為第一門語言。當程式設計者剛起步時，他們不是以團隊撰寫大型程式，而是獨自撰寫小型程式。他們尚無需求使用封裝與命名空間——這些機制是為了讓不同人撰寫的元件得以分別演進。在教授程式設計時，教師會先從「小型程式設計」（programming in the small）的基本概念開始，如變數、控制流程與副程式。於此階段，並不需要「大型程式設計」中的類別、套件與模組等概念。讓語言對新手更友善，符合 Java 資深開發者的整體利益；而資深者也同樣可能希望以更精煉的方式撰寫小型程式，而不必動用任何大型程式設計的構造。

考慮經典的「[Hello, World!](https://zh.wikipedia.org/zh-tw/Hello_World)」範例——這往往是初學者寫的第一個程式：

```java
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello, World!");
    }
}
```

就這個程式所做的事情而言，這裡有太多雜訊——過多的程式碼、概念與語言構造。

- `class` 宣告與強制性的 `public` 存取修飾子，屬於「大型程式設計」的構造。它們在將程式碼封裝為對外介面明確的元件時很有用，但在這個小例子裡毫無必要。  
- `String[] args` 參數同樣是為了把程式碼與外部元件（此處為作業系統的 shell）連接起來而存在。對這裡而言既神祕又無助，尤其因為在像 `HelloWorld` 這類小程式中根本不會用到。  
- `static` 修飾子是語言「類別—物件」模型的一部分。對初學者來說，`static` 不僅難以理解，還有害：若要為此程式加入更多方法或欄位，他們不是得把它們全都宣告為 `static`——從而延續一種既不常見也不是好習慣的用法——就是得面對「靜態成員 vs. 實例成員」的差異，並學會如何具現化（instantiate）物件。  
- 初學者還可能被 `System.out.println` 這句「看似咒語」的寫法困惑，疑惑為何一個簡單的函式呼叫不就夠了。甚至在學習的第一週，他們就可能被迫學會為基本功能匯入工具類別，並納悶為何這些能力不能自動提供。

新手在最不適合的時機遇到這些概念——他們尚未學會變數與控制流程，也尚無法體會「大型程式設計」構造在維持大型程式井然有序方面的價值。教師常會叮嚀：「先別在意，之後你就會懂。」這對教師與學生都不令人滿意，也讓學生留下「這門語言很複雜」的長久印象。

本工作的動機並不僅是減少樣板。我們的目標是幫助剛接觸 Java（或整體程式設計）的人，以正確的順序學習語言：從「小型程式設計」的基礎概念開始，例如進行簡單的文字 I/O，以及用 `for` 迴圈處理陣列；只有在真正有益、且更容易掌握時，才進一步引介「大型程式設計」的進階概念。

此外，本工作的動機也不僅僅是為了幫助初學者。我們希望協助所有撰寫小型程式的人——無論是學生、撰寫命令列工具的系統管理員，或是為最終將用於企業級軟體系統的核心演算法製作原型的領域專家。

我們的提案並非透過改變 Java 語言的結構來讓小型程式更容易撰寫——程式碼仍然被包在方法中，方法包在類別中，類別包在套件中，套件包在模組中——而是把這些細節先隱藏起來，直到它們真正有用時再引入。

## 說明

首先，我們允許 `main` 方法省略那段廣為詬病的樣板 `public static void main(String[] args)`，將 *Hello, World!* 程式簡化為：

```java
class HelloWorld {
    void main() {
        System.out.println("Hello, World!");
    }
}
```

其次，我們引入一種**精簡**原始檔形式，讓開發者無需多餘的類別宣告即可直接撰寫程式碼：

```java
void main() {
    System.out.println("Hello, World!");
}
```

第三，我們在 `java.lang` 套件中新增一個類別，為初學者提供基本的逐行 I/O 方法，藉此以更簡單的寫法取代神秘的 `System.out.println`：

```java
void main() {
    IO.println("Hello, World!");
}
```

最後，對於超越 *Hello, World!*、例如需要基本資料結構或檔案 I/O 的程式，在精簡原始檔中我們會自動匯入一系列超出 `java.lang` 套件範圍的標準 API。

這些變更共同提供了一條「匝道」，也就是一個平緩的坡道，能優雅地匯入主幹道。當初學者邁向更大型的程式時，他們無須丟棄早期學到的內容；相反地，他們會看見這些知識如何融入更大的全貌。有經驗的開發者從原型走向正式產品時，也能順暢地將程式碼成長為大型程式的組成元件。

### 實例 `main` 方法

為了撰寫並執行程式，初學者會先學到程式的**入口點**。現行《Java 語言規範》（JLS）說明，Java 程式的入口點是一個名為 `main` 的方法（[§12.1](https://docs.oracle.com/javase/specs/jls/se24/html/jls-12.html#jls-12.1)）：

> Java 虛擬機器會藉由呼叫某個指定類別或介面的 `main` 方法開始執行，並傳入一個引數，此引數是字串陣列。

JLS 進一步規定（[§12.1.4](https://docs.oracle.com/javase/specs/jls/se24/html/jls-12.html#jls-12.1.4)）：

> `main` 方法必須宣告為 `public`、`static` 且回傳型別為 `void`。它必須宣告一個形式參數，其型別為 `String` 的陣列。

對 `main` 宣告的這些要求屬於歷史遺留，且並非必要。我們可以用兩種方式精簡 Java 程式的入口點：允許 `main` 非 `static`，並移除對 `public` 與陣列參數的要求。如此一來，就能在不使用 `public` 修飾子、不使用 `static` 修飾子，且不需要 `String[]` 參數的情況下撰寫 *Hello, World!*，並將這些構造的介紹延後到真正需要時再引入：

```java
class HelloWorld {
    void main() {
        System.out.println("Hello, World!");
    }
}
```

:span{#launch}

假設這個程式位於檔案 `HelloWorld.java` 中，我們可以用[原始碼啟動器](https://openjdk.org/jeps/330)直接執行它：

```shell
$ java HelloWorld.java
```

或是先明確編譯再執行：

```shell
$ javac HelloWorld.java
$ java HelloWorld
```

無論哪種方式，啟動器都會先啟動 Java 虛擬機器，然後為指定的類別**選擇並呼叫**一個 `main` 方法：

1. 若該類別宣告或繼承了帶有 `String[]` 參數的 `main` 方法，啟動器就選擇那個方法。

    否則，若該類別宣告或繼承了**無參數**的 `main` 方法，啟動器就選擇那個方法。

    否則，啟動器會回報錯誤並終止。

2. 若選到的方法是 `static`，啟動器直接呼叫它。
    否則，該方法就是**實例 `main` 方法**。此時該類別**必須**具有一個**非 `private` 且無參數**的建構子。啟動器會先呼叫該建構子建立物件，再呼叫其所選的 `main` 方法；若沒有符合條件的建構子，啟動器會回報錯誤並終止。

任何能依上述協定被選擇並呼叫的 `main` 方法，稱為**可啟動的**（launchable）`main` 方法。舉例來說，`HelloWorld` 類別有一個可啟動的 `main` 方法，也就是 `void main()`.

### 精簡原始檔

在 Java 語言中，每個類別都位於某個套件中，每個套件又位於某個模組中。模組與套件為類別提供命名空間與封裝；然而，僅由少數類別組成的小型程式並不需要這些概念。因此，開發者可以省略套件與模組宣告；其類別將位於**未命名模組**的**未命名套件**中。

類別為欄位與方法提供命名空間與封裝；但僅由少數欄位與方法組成的小型程式並不需要這些概念。在初學者熟悉變數、控制流程與副程式等基本積木之前，不應要求他們理解這些概念。因此，對僅含少量欄位與方法的小型程式，就像不要求套件或模組宣告一樣，我們也可以不再要求類別宣告。

從今以後，若 Java 編譯器遇到一個原始檔，其中存在未置於類別宣告中的欄位與方法，則會視為該原始檔**隱含宣告**了一個類別，而這個類別的成員正是那些未被包在類別中的欄位與方法。這樣的原始檔稱為**精簡**原始檔。

有了此變更後，*Hello, World!* 就能以精簡原始檔的形式撰寫：

```java
void main() {
    System.out.println("Hello, World!");
}
```

精簡原始檔所**隱含宣告**的類別：

- 是未命名套件中的 `final` 頂層類別；
- 繼承 `java.lang.Object`，且不實作任何介面；
- 具有無參數的預設建構子，且沒有其他建構子；
- 其成員即為該精簡原始檔中的欄位與方法；以及
- 必須具有可啟動（launchable）的 `main` 方法；否則會回報編譯期錯誤。

由於在精簡原始檔中宣告的欄位與方法，會被視為隱含宣告之類別的成員，因此我們可以透過呼叫鄰近宣告的方法來撰寫 *Hello, World!*：

```java
String greeting() { return "Hello, World!"; }

void main() {
    System.out.println(greeting());
}
```

或是透過存取欄位來達成：

```java
String greeting = "Hello, World!";

void main() {
    System.out.println(greeting);
}
```

精簡原始檔是以**隱含方式**宣告類別，因此該類別沒有可在原始碼中使用的名稱。Java 編譯器在編譯精簡原始檔時會產生一個類別名稱，但那是**實作細節**；任何原始碼——包括該精簡原始檔本身——都不應仰賴該名稱。

我們可以透過 `this`（顯式或如上隱式地）參照該類別的目前實例，但**不能**用 `new` 運算子具現化此類別。這反映了一個重要的取捨：若初學者尚未學會類別等物件導向概念，那麼在精簡原始檔中撰寫程式就不應要求類別宣告——而類別宣告正是會賦予可搭配 `new` 使用的類別名稱之所在。

精簡原始檔只是另一種單檔原始碼程式。如[前文](#launch)所示，我們可以用原始碼啟動器直接執行精簡原始檔，或是先明確編譯再執行。

即使隱含宣告的類別不應被其他類別參照、因此無法用來定義 API，`javadoc` 工具仍可從精簡原始檔產生文件。為該隱含類別的成員撰寫文件，對正在學習 `javadoc` 的初學者，以及為大型程式原型化程式碼的資深開發者，都可能有所助益。

### 與主控台互動

初學者常常會撰寫與主控台互動的程式。把訊息寫到主控台理應很直接，但傳統上卻必須呼叫難以理解的 `System.out.println` 方法。對初學者而言，這相當神祕：`System` 是什麼？`out` 又是什麼？

更糟的是從主控台讀取輸入——這本來也應該只是一次簡單的方法呼叫。既然寫到主控台要用 `System.out`，看起來合情合理地，讀取就會用到 `System.in`；但要從 `System.in` 取得一個 `String`，卻需要很多程式碼，例如：

```java
try {
    BufferedReader reader = new BufferedReader(new InputStreamReader(System.in));
    String line = reader.readLine();
    ...
} catch (IOException ioe) {
    ...
}
```

有經驗的開發者或許習慣了這類樣板碼，但對初學者來說，這段程式碼充滿更多的謎團，導致一堆問題：`try` 和 `catch` 是什麼？什麼是 `BufferedReader`？什麼是 `InputStreamReader`？`IOException` 又是什麼？其他做法也存在，但沒有哪一種對初學者而言顯著更好。

為了簡化互動式程式的撰寫，我們新增類別 `java.lang.IO`，其中宣告了五個 `static` 方法：

```java
public static void print(Object obj);
public static void println(Object obj);
public static void println();
public static String readln(String prompt);
public static String readln();
```

初學者現在可以這樣撰寫 *Hello, World!*：

```java
void main() {
    IO.println("Hello, World!");
}
```

接著也能輕鬆寫出最簡單的互動式程式：

```java
void main() {
    String name = IO.readln("Please enter your name: ");
    IO.print("Pleased to meet you, ");
    IO.println(name);
}
```

初學者確實需要學會，這些以「逐行」為主的基本 I/O 方法必須加上限定詞 `IO`，但這不會造成過度的教學負擔。他們很快就會接觸到這類限定詞；例如數學函式需要加上 `Math`，像是 `Math.sin(x)`。

由於 `IO` 類別位於 `java.lang` 套件中，任何 Java 程式都可不經 `import` 而直接使用它。這對所有程式都適用，不僅是精簡原始檔或宣告實例 `main` 方法的程式；例如：

```java
class Hello {
    public static void main(String[] args) {
        String name = IO.readln("Please enter your name: ");
        IO.print("Pleased to meet you, ");
        IO.println(name);
    }
}
```

### 自動匯入 `java.base` 模組

許多 Java 平台 API 的其他類別在小型程式中也很實用。它們可以在精簡原始檔的開頭明確匯入：

```java
import java.util.List;

void main() {
    var authors = List.of("James", "Bill", "Guy", "Alex", "Dan", "Gavin");
    for (var name : authors) {
        IO.println(name + ": " + name.length());
    }
}
```

有經驗的開發者會覺得這很自然，但為了方便，有些人可能傾向使用按需匯入宣告（即 `import java.util.*`）。然而，對初學者而言，任何形式的 `import` 都是另一個謎題，因為它需要理解 Java API 的套件階層。

為了進一步簡化小型程式的撰寫，我們讓 `java.base` 模組所「匯出」之套件中的**公開頂層類別與介面**，在精簡原始檔中皆可直接使用——就好像它們已按需匯入一樣。常用套件如 `java.io`、`java.math` 與 `java.util` 的熱門類別與介面因此可立即使用。在上述範例中，`import java.util.List` 就可以省略，因為 `List` 會自動被匯入。

一份[配套 JEP](https://openjdk.org/jeps/511)則提議一種新的匯入宣告形式：`import module M`，其會按需匯入模組 `M` 所匯出之套件中的所有公開頂層類別與介面。每個精簡原始檔都被視為自動匯入 `java.base` 模組，就彷彿在檔案開頭出現了：

```java
import module java.base;
```

換言之，這段宣告被隱式地加在每個精簡原始檔的最前面。

### 擴展程式

精簡原始檔中的小型程式聚焦於**程式要做什麼**，省略它不需要的概念與構造。即便如此，其中所有成員的詮釋方式仍與一般類別相同。要把精簡原始檔演進為一般原始檔，我們只需將其中的欄位與方法包進一個**明確的** `class` 宣告，並加入匯入宣告即可。舉例來說，以下這個精簡原始檔：

```java
void main() {
    var authors = List.of("James", "Bill", "Guy", "Alex", "Dan", "Gavin");
    for (var name : authors) {
        IO.println(name + ": " + name.length());
    }
}
```

可以演進成宣告單一類別的一般原始檔：

```java
import module java.base;

class NameLengths {
    void main() {
        var authors = List.of("James", "Bill", "Guy", "Alex", "Dan", "Gavin");
        for (var name : authors) {
            IO.println(name + ": " + name.length());
        }
    }
}
```

`main` 方法本身完全不需要改動。因此，將小型程式轉成可作為大型程式元件的類別，一直都很直接。

## 替代方案

### 自動匯入主控台 I/O 方法

在此功能較早期的預覽中，我們曾探索讓精簡原始檔自動匯入新 `IO` 類別的 `static` 方法。如此一來，開發者在精簡原始檔中可以寫 `println(...)`，而非 `IO.println(...)`。

這麼做的效果頗為悅目：`IO` 裡的方法看起來就像是 Java 語言的內建功能。然而，它也在「匝道」上增添了一個減速帶：要把精簡原始檔演進為一般原始檔，初學者就必須新增 `static` 匯入宣告——這又是另一個進階概念。這與我們的第二個目標相悖，也就是讓初學者能**優雅地**擴充他們的程式碼。此設計還會帶來長期負擔：必須不斷審查源源不絕、要求替 `IO` 類別再加入更多方法的提案。

### 自動匯入較少的套件

與其將 `java.base` 模組中的全部 54 個套件自動匯入精簡原始檔，我們也可以只匯入其中一部分——但究竟是哪一些？

每位讀者大概都有自己的名單，覺得哪些套件應該在每個小程式中自動匯入：`java.io` 與 `java.util` 幾乎是全民共識；`java.util.stream` 與 `java.util.function` 也相當常見；`java.math`、`java.net` 與 `java.time` 也各有擁護者。以 JShell 工具為例，我們曾經找出十個在一次性 Java 試驗程式中普遍有用的 `java.*` 套件；但要決定哪個 `java.*` 子集合值得被**永久且自動**匯入到每個精簡原始檔，卻相當困難。更何況，清單還會隨著 Java 平台演進而改變；例如 `java.util.stream` 與 `java.util.function` 直到 Java 8 才引入。開發者很可能會依賴 IDE 來提示哪些自動匯入生效——這是我們不樂見的結果。

將 `java.base` 模組所匯出的所有套件一併匯入，對於精簡原始檔隱含宣告的類別而言，是一致且合理的選擇。

### 允許頂層敘述

另一種設計是允許在精簡原始檔中直接撰寫敘述，而不必宣告 `main` 方法。此設計會將整個精簡原始檔視為隱含宣告之類別的隱含 `main` 方法本體。

不幸的是，這樣的設計會受限，因為在精簡原始檔中將無法宣告方法。這些方法會被解讀為出現在看不見的 `main` 方法的本體內，但方法不能在方法內宣告，因此會不合法。精簡原始檔只能表達一行接一行的線性程式，而無法將重複計算抽象成副程式。

此外，在此設計下，所有變數宣告都會被解讀為該看不見的 `main` 方法的區域變數。這也有侷限，因為區域變數只有在「實質上為 final（effectively final）」時，才能從 lambda 運算式中存取——這屬於進階概念。於是，在精簡原始檔中撰寫 lambda 運算式將既容易出錯又令人困惑。

我們認為，想要在方法本體之外、直接在精簡原始檔中撰寫敘述的需求，主要源自於撰寫 `public static void main(String[] args)` 的痛點。既然已讓 `main` 方法更容易宣告，我們認為精簡原始檔最好仍由方法與欄位組成，而非直接由敘述構成。

### 擴充 JShell

[JShell](https://openjdk.org/jeps/222) 是一個可即時執行 Java 程式碼的互動式工具。它提供逐步式的程式設計環境，讓初學者能在不需太多儀式的情況下進行實驗。

另一種設計是擴充 JShell 以達成我們的目標。理論上頗具吸引力，但在實務上較不理想。

JShell 工作階段並不是一個 Java 程式，而是一連串的**程式碼片段**。片段逐一執行，但彼此並非獨立：目前片段的執行取決於先前所有片段的結果，因此數值與宣告會隨時間看似「演進」。在任何時刻，都有一個「當前狀態」的概念，但缺乏實際的文字化程式表示。這對「實驗」——JShell 的主要用途——很有效，但並非協助初學者撰寫真實程式的理想基礎。

再從技術層面看，JShell 工作階段中的所有宣告都被解讀為某個未指定類別的 `static` 成員，而所有敘述都在「先前所有宣告皆在可見範圍內」的情境中執行。若我們將精簡原始檔解讀為一系列程式碼片段，那麼該檔案只能表達其方法與欄位皆為 `static` 的類別，等同引入一種 Java 方言。要把精簡原始檔演進為一般原始檔，將必須在每個方法與欄位宣告上加上 `static` 修飾子，阻礙小型程式向大型程式**優雅**演進。

### 引入新的 Java 語言方言

更激進的設計是為精簡原始檔定義一種不同的語言方言，以追求更大的簡潔度，並移除各種要素。比方說，我們可以取消 `main` 方法必須顯式宣告為 `void` 的要求。然而，這將阻礙小型程式**優雅**演進為大型程式，而後者是更重要的目標。我們寧可提供一條平順的「匝道」，而不是把人帶到懸崖邊。
